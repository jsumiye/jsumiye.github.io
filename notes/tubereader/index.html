YouTube in, article out

2025 · on hold

I got tired of watching a video a second time in order to write it down. TubeReader takes a YouTube URL and returns a formatted article. Title, tone, theme, length, language. Public, unlisted, or private, the same way you already think about a video.

The site is on hold. Other work jumped the queue. A limited demo still runs at tubereader.practicalsoftware.com.

Generate is a set of knobs, not a magic button

The generate screen is where the product opinion lives. A transcript is not an article. Someone has to pick a tone, a length, a font, a language. I would rather those choices be visible than hidden in a prompt I will forget.

Custom titles go through the same model with a narrower job. Is this title alright for a general audience. That is not a content-policy department. It is a cheap check so a public article does not ship a title I would not put on a school computer.

Two APIs, plus one I had to host

YouTube Data API v3 is polite. It gives metadata if you ask correctly. Transcripts are ruder. I self-hosted a Flask service on Railway that wraps a transcript library, because I did not want the PHP app talking to a moving target on someone else's laptop. 

POST /article
{
  "url": "https://www.youtube.com/watch?v=...",
  "tone": "plain",
  "length": "medium",
  "visibility": "unlisted",
  "language": "en"
}

PHP stores the result. React renders the dashboard and the explore grid with Material UI, MUI X, and Swiper. Explore is the public shelf. Dashboard is the workshop, and it requires a login.

The unglamorous bits

Registrations go through UserCheck so a disposable inbox does not become an account. Batch upload and long videos were next. They are still next. A SaaS is a pile of those sentences.

What I learned is less "I used React" and more this. Once people can log in, you are on the hook for visibility bugs. An unlisted article that shows up on Explore is not a styling issue. It is the whole product failing in one query.
